# 十题三组对照实验

状态：**已设计并完成离线程序自测；尚无真实模型对照输出或真人学习效果数据。** 此处不能据此声称 theo-lens 优于普通提问或已形成壁垒。

## 比较什么

10个跨领域题目，每题在独立请求中比较三组：A 原始问题；B 通用结构化提示词（定义、例子、机制、边界）；C 加载完整 theo-lens。默认同一模型、同一系统约束、相同调用参数，各题顺序固定种子随机排列。三组均不提供网页检索；对需要实时外部数据的问题应注明不能核验。本题集使用稳定的假设场景。Crypto 为技能内置例子，标注为**已见案例**，不当作未见泛化证据。

C组会把 skill 正文发给模型；所有条件均不附 `check` 答案。请勿用于上传用户隐私。运行一次是30个付费API调用，用户应自行查看模型价格。不同模型可能不支持脚本默认的 temperature 参数，应以实际API能力调整，结果必须记录设置。

## 运行

在本目录执行：

```bash
python benchmark.py --mode dry-run --out runs/dry-run
```

产生30条请求计划但不调用模型，不构成真实结果。真实运行需自行配置兼容 OpenAI Chat Completions 的服务和 `OPENAI_API_KEY`，并指定模型：

```bash
python benchmark.py --mode run --model YOUR_MODEL --out runs/experiment-01
```

默认访问 `https://api.openai.com/v1/chat/completions`；也可通过 `--url` 指定信任的兼容端点。不要在任何文档中记录API密钥。调用权限、费用和网络由运行者自行确认。每次使用新的输出目录；网络或权限错误会中止并保留已完成的中间记录。

输出 `blind.jsonl` 中每条仅给出随机编号、题目和答案；`key.json` 保存编号与组别对应关系，盲评结束前不应打开。`requests.jsonl` 含实际请求和分组，需与盲评材料分开。`raw.jsonl` 含原始回答与模型报告的token用量，仅在真实运行后产生；请注意平台隐私。代码顺序随机，编号可复现；它不能自动消除评分者识别写作风格的风险。

## 评分与学习效果

针对每条答案，由未见组别的评审使用 `rubric.json` 打分：事实及计算准确、问题起点、机制和案例、反例边界、清晰度，每项0–2分。严重错误单独标记，并记录字数和模型报告的token；有争议时复核。评分卡只评回答质量，不可当成学习成效。

检验学习效果需另外招募真实学习者，随机分配组别，独立测量前测、阅读时间、后测迁移题以及适当间隔后的延迟测验。不要让同一人依次阅读同一题的三种答案。10题是探索性样本，不能支持普遍化结论；模型、题目和评分者选择都会影响结果。完整报告应保留所有失败样本和测量口径，不挑选最好结果。
